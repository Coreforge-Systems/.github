# Участие в разработке Coreforge Systems

## Инженерные принципы

- Надёжность важнее удобства.
- Явное управление состоянием и обработка ошибок.
- Никакого скрытого блокирующего ввода-вывода в коде GUI.
- Чёткие архитектурные границы.
- Возможность тестирования без физического оборудования, где это возможно.
- Диагностика по умолчанию работает только на чтение.
- Никаких небезопасных повторов неидемпотентных команд устройства.
- Никаких секретов или конфиденциальных данных клиентов в коммитах, журналах, тестовых данных или тестах.

## Рабочий процесс

1. Создайте отдельную ветку от `main` для конкретной задачи.
2. Ограничивайте каждое изменение одной логической целью.
3. Добавляйте или обновляйте тесты при изменении поведения.
4. Локально запускайте форматирование, статический анализ, сборку и тесты.
5. Откройте pull request с использованием шаблона организации.
6. Не выполняйте слияние, пока обязательные проверки завершаются с ошибками.

### Имена веток

```text
feature/
fix/
refactor/
test/
docs/
build/
ci/
chore/
```

Примеры:

```text
feature/device-identification
fix/frame-decoder-overflow
refactor/operation-scheduler
test/protocol-timeout
docs/demo-protocol-v1
```

## Сообщения коммитов

```text
feat: add device identification request
fix: reject oversized protocol frames
refactor: isolate operation timeout handling
test: add delayed response integration case
docs: document support package schema
```

## Требования к C++

- Предпочитайте RAII и явно определённое владение объектами.
- Избегайте сырых владеющих указателей.
- Сохраняйте публичные API минимальными.
- Избегайте ненужного глобального состояния.
- Считайте предупреждения компилятора дефектами.
- Не блокируйте потоки GUI Qt.
- Документируйте привязку к потоку и владение для компонентов на основе `QObject`.

## Тестирование

Изменения в обмене с устройствами должны охватывать как успешные, так и ошибочные сценарии там, где это применимо: тайм-аут, разрыв соединения, некорректные входные данные, неподдерживаемые операции, недопустимые параметры, отмену и запоздалые ответы.

## Безопасность

Не включайте в коммиты пароли, токены API, закрытые ключи, протоколы клиентов под NDA, учётные данные производственных систем, персональные данные или диагностические пакеты без удаления конфиденциальных сведений.
